# AI测试控制台 - 快速入门

## 🚀 5分钟上手指南

### 第一步：启动服务

确保两个服务都在运行：

```bash
# 后端服务（Terminal 38）
python backend_api_server.py

# 前端服务（Terminal 6）
cd frontend
npm run dev
```

### 第二步：打开控制台

浏览器访问：**http://localhost:5173/ai-test-console**

### 第三步：输入测试信息

1. **需求描述**（必填）
   ```
   示例：支付模块需要支持微信支付和支付宝支付
   ```

2. **Git Diff**（可选）
   ```
   +def wechat_pay():
   +    return process_payment('wechat')
   ```

3. **优先级**（选择一个）
   - P0: 核心功能（高风险，全面测试）
   - P1: 重要功能（中风险，重点测试）
   - P2: 一般功能（低风险，基础测试）

### 第四步：执行测试

点击 **🚀 Run AI Test** 按钮

### 第五步：查看结果

系统会实时显示5个阶段的执行进度：

1. **🤖 AI决策分析** - 判断是否需要测试
2. **📋 生成测试策略** - 确定测试范围
3. **⚡ 执行测试** - 自动运行测试
4. **🔧 自动修复** - 失败用例修复
5. **📊 生成报告** - AI分析总结

## 📊 结果解读

### AI决策卡片
- **是否执行**: ✅需要测试 / ⏭️跳过
- **优先级**: P0/P1/P2
- **风险等级**: 高/中/低
- **置信度**: 0-100%

### 测试策略卡片
- **模块列表**: 显示所有测试模块
- **测试类型**: api, ui, integration
- **执行顺序**: 按优先级排序

### 执行过程卡片
- **统计数据**: 总数/通过/失败
- **详细结果**: 每个模块的执行状态
- **耗时**: 每个模块的执行时间

### 自愈过程卡片
- **修复次数**: 总共尝试修复的次数
- **成功修复**: 成功修复的数量
- **修复记录**: 详细的修复策略

### 最终报告卡片
- **状态**: passed/failed/skipped/partial
- **通过率**: 百分比和进度条
- **AI分析**: 智能总结和建议
- **时间线**: 各阶段耗时分布
- **Trace ID**: 全链路追踪ID

## 💡 使用技巧

### 什么时候用AI控制台？

✅ **适合场景**:
- 代码提交前快速验证
- 小功能变更的回归测试
- Bug修复后的验证
- 日常开发中的快速检查

❌ **不适合场景**:
- 新功能需要完整测试文档
- 需要导出测试用例Excel
- 需要生成自动化脚本文件
- 复杂业务逻辑的全面测试

### 什么时候用传统流程？

访问 **http://localhost:5173/projects** 使用传统流程：
- 上传需求文档和Swagger
- 生成完整测试用例Excel
- 生成pytest自动化脚本
- 导出企业级测试报告

## 🔍 追踪和调试

### 使用Trace ID
每次执行都会生成唯一的Trace ID，可以用于：
- 查询历史执行记录
- 追踪问题定位
- 性能分析

### 查询API
```bash
# 查询特定Trace
GET /api/pipeline/trace/{trace_id}

# 查询历史记录
GET /api/pipeline/history?limit=10

# 查询统计信息
GET /api/pipeline/statistics
```

## 🆘 常见问题

### Q1: 执行时间过长？
A: 检查Ollama服务是否正常，可以切换到更快的模型（qwen2.5:1.5b）

### Q2: AI判断不准确？
A: 提供更详细的需求描述和Git Diff，帮助AI更好地理解变更

### Q3: 测试失败怎么办？
A: 查看自愈过程卡片，系统会自动尝试修复并重试

### Q4: 如何导出报告？
A: 当前版本暂不支持导出，可以复制Trace ID后使用API查询
