## 📝 输入区域

### 1. 需求描述（必填）
- **位置**: 左上方
- **类型**: 多行文本框
- **示例**: "支付模块需要支持微信支付和支付宝支付"
- **说明**: 清晰描述功能需求，AI会根据此判断是否需要测试

### 2. Git Diff（可选）
- **位置**: 左中
- **类型**: 代码文本框（等宽字体）
- **示例**: 
  ```
  +def wechat_pay():
  +    return process_payment('wechat')
  ```
- **说明**: 提供代码变更，帮助AI更准确判断影响范围

### 3. 优先级选择
- **位置**: 左下
- **类型**: 按钮组
- **选项**: 
  - **P0**: 核心功能（红色标签）
  - **P1**: 重要功能（黄色标签）
  - **P2**: 一般功能（蓝色标签）
- **说明**: 影响测试策略的生成

### 4. 执行按钮
- **位置**: 底部
- **样式**: 蓝色渐变大按钮
- **状态**: 
  - 正常: "🚀 Run AI Test"
  - 执行中: "⚙️ 执行中..."（带旋转动画）
  - 禁用: 需求为空时禁用

## 🎨 颜色编码

### 状态颜色
- 🟢 **绿色**: 通过、成功、健康
- 🔴 **红色**: 失败、错误、高风险
- 🟡 **黄色**: 警告、中风险、部分通过
- ⚪ **灰色**: 等待、跳过、未执行

### 优先级颜色
- 🔴 **P0**: 红色背景（核心功能）
- 🟡 **P1**: 黄色背景（重要功能）
- 🔵 **P2**: 蓝色背景（一般功能）

### 风险等级颜色
- 🔴 **高**: 红色标签
- 🟡 **中**: 黄色标签
- 🟢 **低**: 绿色标签

## 🔄 交互流程

### 正常流程
```
1. 用户输入需求
   ↓
2. 点击"Run AI Test"
   ↓
3. 按钮变为"执行中..."（禁用输入）
   ↓
4. 显示进度指示器（5个阶段）
   ↓
5. 当前阶段高亮+动画
   ↓
6. 完成后显示结果卡片
   ↓
7. 按钮恢复，可以继续测试
```

### 清空流程
```
1. 点击"清空"按钮
   ↓
2. 清空所有输入框
   ↓
3. 重置优先级为P1
   ↓
4. 清除结果显示
   ↓
5. 准备下一次测试
```

## 🎯 使用提示

### 提示1: 需求描述要清晰
❌ 不好: "改了一些东西"  
✅ 好: "支付模块新增微信支付功能"

### 提示2: 合理选择优先级
- P0: 支付、登录、核心业务
- P1: 查询、统计、重要功能
- P2: 日志、配置、辅助功能

### 提示3: 善用Git Diff
提供代码变更可以帮助AI：
- 更准确判断影响范围
- 更合理评估风险等级
- 更精准生成测试策略

### 提示4: 关注AI分析
AI分析会提供：
- 测试结果总结
- 风险评估
- 改进建议
- 后续行动
