# AI测试控制台 - 双模式使用指南

## 🎯 概述

AI测试控制台现在支持两种执行模式,满足不同场景的测试需求:

- **⚡ 仅决策分析 (快速)**: 2-5秒,只判断是否需要测试
- **🚀 完整流程 (5阶段)**: 10-20秒,执行完整测试流程

## 📍 访问方式

```
http://localhost:5173/ai-test-console
```

| 特性 | 仅决策分析 | 完整流程 |
|------|----------|---------|
| **耗时** | 2-5秒 ⚡ | 10-20秒 🔄 |

| **AI决策** | ✅ | ✅ |
| **测试策略** | ❌ | ✅ |

| **自动修复** | ❌ | ✅ |
| **生成报告** | ❌ | ✅ |
| **优先级选择** | ❌ | ✅ |
| **适用场景** | 快速检查 | 完整验证 |

## 📖 使用方法

### 模式1: 仅决策分析 (快速)

**适用场景**:
- ✅ 代码提交前快速检查
- ✅ 判断变更是否需要测试
- ✅ 评估风险和优先级
- ✅ 不需要实际执行测试

**操作步骤**:
```
1. 打开 AI测试控制台
2. 执行模式: 选择 "仅决策分析 (快速)"
3. 输入需求描述 (必填)
4. 输入 Git Diff (可选)
5. 点击 "⚡ 快速决策"
6. 2-5秒后查看决策结果
```

**输出内容**:
- 是否需要测试 (✅/⏭️)
- 优先级 (P0/P1/P2)
- 风险等级 (高/中/低)
- 置信度 (0-100%)
- 影响模块
- 决策原因

**示例**:
```
需求: "修复订单计算bug"
Git Diff: "- total = price * quantity
          + total = price * quantity * discount"

结果:
✅ 需要测试
优先级: P0 (核心功能)
风险等级: 高
置信度: 95%
影响模块: 订单模块、支付模块
```

### 模式2: 完整流程 (5阶段)

**适用场景**:
- ✅ 完整的测试验证
- ✅ 需要测试执行结果
- ✅ 需要自动修复功能
- ✅ 需要完整测试报告

**操作步骤**:
```
1. 打开 AI测试控制台
2. 执行模式: 选择 "完整流程 (5阶段)"
3. 输入需求描述 (必填)
4. 输入 Git Diff (可选)
5. 选择优先级 (P0/P1/P2)
6. 点击 "🚀 Run AI Test"
7. 10-20秒后查看完整结果
```

**执行流程**:
```
1️⃣ AI决策分析 (2-5秒)
   ├─ 判断是否需要测试
   ├─ 评估风险等级
   └─ 输出决策指令

2️⃣ 生成测试策略 (<1秒)
   ├─ 应用业务规则
   ├─ 生成测试计划
   └─ 确定测试类型

3️⃣ 执行测试 (0.5秒)
   ├─ 并行调度测试
   ├─ 运行测试用例
   └─ 收集执行结果

4️⃣ 自动修复 (如需要)
   ├─ 分析失败原因
   ├─ 应用修复策略
   └─ 自动重试验证

5️⃣ 生成报告 (<1秒)
   ├─ 统计测试结果
   ├─ AI总结风险点
   └─ 生成完整报告
```

**输出内容**:
- AI决策结果
- 测试策略详情
- 执行过程统计
- 自愈过程记录
- 最终测试报告
- 执行时间线
- Trace ID

## 💡 使用技巧

### 1. 如何选择模式?

**选择"仅决策分析"如果**:
- ⚡ 只想快速判断是否需要测试
- ⚡ 代码提交前的快速检查
- ⚡ 评估变更的影响范围
- ⚡ 时间紧迫,需要快速反馈

**选择"完整流程"如果**:
- 🔄 需要实际执行测试
- 🔄 需要测试覆盖率报告
- 🔄 需要自动修复功能
- 🔄 需要完整的测试文档

### 2. 需求描述建议

**好的示例** ✅:
```
"支付模块需要支持微信支付,包括扫码支付和H5支付"
"修复订单计算bug,折扣计算不正确"
"用户登录功能添加验证码,防止暴力破解"
```

**不好的示例** ❌:
```
"改了点代码"
"修复bug"
"更新功能"
```

### 3. Git Diff 建议

**包含关键信息** ✅:
```diff
+def wechat_pay(order_id, amount):
+    # 调用微信支付API
+    return process_payment('wechat', order_id, amount)
```

**避免过长** ❌:
- 只粘贴关键变更
- 不要粘贴整个文件
- 不要包含无关的格式化变更

### 4. 优先级选择 (仅完整流程)

- **P0**: 支付、登录、订单等核心功能
- **P1**: 用户管理、商品管理等重要功能
- **P2**: 日志、配置等一般功能

## 🔄 模式切换

可以随时在两种模式之间切换:

```
仅决策分析 → 完整流程
- 如果决策结果显示需要测试
- 想要查看详细的测试结果
- 需要自动修复功能

完整流程 → 仅决策分析
- 只想快速判断
- 不需要实际执行测试
- 节省时间
```

## 🆘 常见问题

### Q1: 两种模式有什么区别?

**A**: 仅决策模式只做AI分析判断,不执行实际测试;完整流程模式会执行5个阶段,包括测试执行和自动修复。

### Q2: 什么时候用仅决策模式?

**A**: 当你只想快速判断是否需要测试,或者代码提交前快速检查时使用。

### Q3: 什么时候用完整流程模式?

**A**: 当你需要实际执行测试,获取测试结果和报告时使用。

### Q4: 可以随时切换模式吗?

**A**: 可以!在执行前随时切换,不影响已有结果。

### Q5: 仅决策模式的结果准确吗?

**A**: 准确!使用相同的AI模型和算法,只是不执行后续的测试阶段。
