## 2. 变更清单

### 2.1 数据库
| 变更 | 说明 |
|------|------|
| 新增表 `iteration_execution_set_cases` | 执行集-用例关联表 (id, execution_set_id, test_case_id, created_at) |
| 新增模型 `IterationExecutionSetCase` | SQLAlchemy ORM 模型，双向关联 |
| 迁移脚本 | `scripts/migrate_d2_3a_1_execution_closure.py` |

### 2.2 后端 API 增强

#### POST /api/v2/iterations/{id}/execution-sets（增强）
- 按 type 智能选择用例：
  - `smoke`: P0/P1 + high risk/priority，不足时取前5
  - `iteration`: 当前迭代全部用例
  - `regression`: 当前迭代 + 历史 regression 标签用例（无则 fallback）
- 写入 `iteration_execution_set_cases` 关联记录
- 返回 `case_ids` 列表

#### POST /api/v2/iterations/{id}/run（重写）
- 支持 `execution_set_id` 参数（默认取最新 iteration 类型执行集）
- 从 `iteration_execution_set_cases` 获取用例列表
- 创建真实 `TestRun` + `RunCase` 记录
- 调用 `ExecutionEngineV2.execute_case()` 执行每个用例
- 真实 HTTP 请求 → 断言校验 → 结果写入
- 更新 `RunCase` 状态、`TestRun` 统计、`ExecutionSet` 状态
- 更新 `TestCase.last_run_status` 和 `failure_category`
- 执行集状态机：created → running → passed/failed/partial/error

#### GET /api/v2/iterations/{id}/report（增强）
- 新增字段：`executed_cases`, `pass_rate`, `latest_run_id`, `execution_sets`
- 新增 `failure_categories`：从 RunCase 聚合真实失败分类
- 新增 `risk_summary`：P0/P1 失败统计
- 新增 `release_recommendation`：pass / conditional_pass / block
- 新增 `release_reason`：决策理由文字

### 2.3 前端增强

#### 执行集 Tab
- 每个执行集卡片显示彩色状态标签 (created/running/passed/failed/partial/error)
- 新增"执行"按钮，直接触发指定执行集的真实执行
- 执行完自动刷新列表

#### 报告 Tab
- 新增**发布建议**卡片（✅可发布 / ⚠️有条件发布 / 🚫阻塞发布）
- 统计从 4 格升级为 5 格（新增"已执行"）
- 新增**失败分类**面板
- 新增**风险摘要**面板（P0/P1 失败数）
- 执行记录表新增"耗时"列和状态颜色标签

### 2.4 API 层
- `api.js` 的 `run()` 方法支持传入 `{execution_set_id}` body

## 3. 执行引擎复用说明

复用路径：`app/executor_v2/execution_engine.py` → `ExecutionEngineV2`
- `HttpRunner`：真实 HTTP 请求（httpx）
- `AssertionEngineV2`：断言校验
- `ResultWriter`：结果持久化
- `_prepare_environment_auth`：认证注入（Bearer/Basic/OAuth2/APIKey）
- `_classify_failure_category`：8 类失败分类

**未新建任何执行引擎，100% 复用现有组件。**
