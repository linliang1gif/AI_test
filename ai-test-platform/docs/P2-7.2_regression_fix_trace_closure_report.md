## 1. P1-7D Real Mode Safety 失败原因和修复

**失败原因**: 测试脚本调用 `PUT /admin/app-mode?mode=real` 切换应用模式，该端点要求 `TESTING=true` 环境变量或 `X-Testing-Key` header。后端启动时未设置 `TESTING=true`，导致返回 403 `ADMIN_APP_MODE_DISABLED`。

**修复**: 以 `TESTING=true` 和 `TESTING_KEY=regression_test_key_2026` 环境变量启动后端进程。回归运行器 `run_regression_all.py` 已在 line 85 将 `TESTING=true` 和 `TESTING_KEY` 传递给子进程。

**结果**: ✅ PASS (80.4s)

## 2. P1-7E Report Persistence 失败原因和修复

**失败原因**: 同 P1-7D，测试依赖 `/admin/app-mode` 端点进行模式切换，后端未启用 TESTING 模式。

**修复**: 同上。

**结果**: ✅ PASS (34.4s)

## 3. P2-6 Playwright Enhanced 失败原因和修复

**失败原因**: 测试中 2/30 项为 `eval_js` real-mode 拦截测试，需要通过 `/admin/app-mode` 切换到 real 模式。后端未启用 TESTING 模式导致模式切换失败，进而导致 eval_js 在 mock 模式下执行成功（而测试期望被拦截）。

**修复**: 同上。后端以 `TESTING=true` 启动后，模式切换正常，eval_js 在 real 模式下被正确拦截。

**结果**: ✅ PASS (96.8s, 30/30)
