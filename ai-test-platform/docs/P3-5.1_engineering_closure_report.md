## 一、P4_intelligence_roadmap.md 更新

### 1.1 P3-5 风险公式对齐

**旧版（已废弃）**：
```
风险分 = 历史失败率 × 0.4 + 最近变更频率 × 0.3 + (1 - 测试覆盖率) × 0.3
```

**实际实现（8 因子）**：
```
case_risk_score =
  历史失败率        × 0.25
+ 最近失败权重      × 0.20
+ 用例优先级权重    × 0.15
+ 所属模块风险      × 0.15
+ 未关闭缺陷影响    × 0.10
+ flaky 影响        × 0.05
+ 数据问题影响      × 0.05
+ 最近门禁失败影响  × 0.05
```

**差异说明**：
1. 代码变更频率暂未纳入 — 当前未接 Git 变更分析
2. 测试覆盖率缺口暂未纳入 — 当前未接代码覆盖率采集
3. 当前基于历史执行数据、缺陷、门禁、数据问题、Flaky 的规则推荐
4. 后续如接入 Git 和覆盖率，可升级为 P3-5B

## 四、回归分层

### 4.1 设计

| Profile | 脚本数 | 内容 | 用途 |
|---------|--------|------|------|
| `smoke` | 2 | P0-7 冒烟 + API 契约 | 快速验证，<30s |
| `core` | 22 | 主链路（不含 external_api / AI 依赖） | 日常开发验证 |
| `full` | 24 | 全量（默认） | 阶段交付验证 |

### 4.2 使用方式

```bash
python scripts/run_regression_all.py --profile smoke
python scripts/run_regression_all.py --profile core
python scripts/run_regression_all.py --profile full   # 默认
python scripts/run_regression_all.py                  # 等同 full
```

### 4.3 分层标签

每个脚本条目新增第 6 个字段（set），标识所属分层：
- `{"smoke","core","full"}` — 冒烟级
- `{"core","full"}` — 核心级
- `{"full"}` — 仅全量（external_api / AI 依赖）

## 五、AI 测试策略

### 5.1 P3-6 前置策略

| 场景 | 策略 |
|------|------|
| `AI_PROVIDER=none` | P3-6 只验证 ai_generated 标记、prompt_version 字段、执行效果统计。不调用真实 LLM。核心回归不因此 FAIL。 |
| `AI_PROVIDER` 可用 | 验证 AI 生成、AI 评审、AI 自愈等真实调用链路。 |
| P1-8A / P1-8 长期 SKIP | 标记为外部 AI 依赖。P3-6 不强依赖它们。可新增 AI provider smoke check（可选执行）。 |

### 5.2 原则

1. P3-6 核心功能（标记追踪 + 效果统计）不依赖 LLM
2. LLM 调用链路作为增强层，`AI_PROVIDER=none` 时自动降级
3. 不因 AI Provider 不可用导致核心回归 FAIL
