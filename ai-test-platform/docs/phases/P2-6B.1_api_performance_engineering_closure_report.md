## 3. test_phase18 的 12 个 timeout 具体原因

### 失败接口分析

| 区段 | 失败数 | 接口 | 原因 |
|------|--------|------|------|
| 4.1-4.11 | 11 | `POST /api/v2/test-cases/batch-execute` (preset=smoke) | 批量执行 100+ 用例，每个用例调用后端 HTTP 引擎向目标 API 发送真实请求。当目标 API 不可达或响应慢，60s 超时。 |
| 8.1-8.3 | 3 | `POST /api/v2/test-cases/batch-execute` (preset=query-safe) | 同上，query-safe preset 批量执行超时。 |

**根本原因**：
- `batch-execute` 内部使用 `ExecutionEngineV2` 对每个用例发送真实 HTTP 请求
- Demo 环境的 Mock API 在批量并发下可能响应缓慢
- 不是代码 bug，而是运行环境的外部依赖超时

### 是否依赖真实外部服务？

**是**。`batch-execute` 会调用 environment 中配置的 `base_url` 对应的服务。在 CI/测试环境中，Mock API 服务需要在同一进程中启动并响应。

### 是否影响核心主链路？

**否**。Phase 18 验收的核心功能（summary 增强、destructive 跳过、failure_category 分类、HTML 报告增强）在超时前的 section 1-3 和超时后的 section 5-7, 9-10 中均正常验证。
