# P3-4A.1: 质量驾驶舱回归稳定性收口报告

## 概述
P3-4A 质量驾驶舱 MVP 专项测试 76/76 PASS，但 run_regression_all 中 P2-3 FAIL。
本轮目标：修复 P2-3 失败，确保 FAIL=0。不新增功能，不进入 P3-4B。

## 一、P2-3 失败真实原因

### 原因 1: 后端 readiness race（连接瞬断）
- **失败请求**: `GET /health`（`test_p2_3_web_ui_case_model.py` 第 46 行）
- **失败时机**: 脚本启动时，后端尚未完全恢复
- **根因**: `run_regression_all.py` 只在启动时检查一次 `/health`，后续 22 个测试脚本之间无 readiness 复查
- **表现**: `WinError 10061` 连接拒绝，`ConnectionError` 未被捕获，脚本直接崩溃
- **P2-3 脚本缺陷**: `api()` 函数直接调用 `requests.get`，无重试逻辑

### 原因 2: 数据积累导致分页溢出
- **失败断言**: "列表中能找到 Web UI 用例" 和 "筛选结果包含刚创建的用例"
- **根因**: 多次回归运行累积了 **545 条** web_ui 类型测试用例，超过查询 `limit=500`
- **表现**: 新创建的用例排在第 545+ 位，`limit=500` 的查询无法返回

### 是否为后端 readiness race
**是**。`run_regression_all.py` 在启动后端后仅检查一次 `/health`，后续各脚本执行前不再确认。
经过多个重计算密集的测试（Phase 18 耗时 153s），后端可能因资源压力暂时不响应。

### analytics 路由是否影响后端启动
**否**。`analytics_service.py` 在 import 时不执行任何 DB 查询，所有查询在函数调用时才发生。
`analytics_routes.py` 注册在 `router_registry.py` 中，使用标准 `_safe_import` 保护，异常安全。

## 二、修复内容

### 修改 1: `scripts/run_regression_all.py` — 每脚本前 readiness 检查
- 新增 `ensure_backend_ready()` 函数
- 优先检查 `/readiness`，回退 `/health`
- 最多等待 30 秒，每 1 秒重试
- 超时时明确输出 `Backend readiness timeout`
- 每个脚本执行前调用，超时则标记 FAIL 并跳过

### 修改 2: `scripts/test_p2_3_web_ui_case_model.py` — 启动容错
- 新增 `wait_for_backend()` 函数（30 秒重试，优先 /readiness）
- 脚本开始前调用，超时则 `sys.exit(1)`，不产生未处理异常
- 业务断言失败不受重试影响

### 修改 3: `scripts/test_p2_3_web_ui_case_model.py` — 分页溢出修复
- 列表查询 `limit` 从 500 提升至 5000（API 最大值）
- 适配 545+ web_ui 测试用例的数据积累场景
