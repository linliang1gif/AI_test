# 蓝点接口响应规范分析

基于 dev-recycle.szhibu.com 开发环境真实接口响应分析。

## 1. 统一响应结构

所有业务接口返回固定三字段:

```json
{
  "code": 200,
  "message": "SUCCESS",
  "data": ...
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 业务状态码, 200=成功 |
| message | string | 状态描述 |
| data | any | 业务数据, 失败时为 null |

## 2. 业务状态码 code

| code | 含义 | 场景 |
|------|------|------|
| 200 | 业务成功 | 正常请求 |
| 401 | 认证失败 | Token缺失/过期/无效 |
| 400 | 业务错误 | 参数错误、数据不存在 |
| 10000 | 参数校验失败 | 缺少必填字段 (如 "pageNum not null") |

**关键: HTTP 状态码始终为 200, 业务成败由 body.code 决定。**

## 3. 认证失败

HTTP 200, body.code = 401:

```json
{
  "code": 401,
  "message": "Cannot convert access token to JSON",
  "data": null
}
```

无 Token 时:

```json
{
  "code": 401,
  "message": "Full authentication is required to access this resource",
  "data": null
}
```

## 4. 消息字段

固定使用 `message` (不是 `msg`)。

## 5. 分页接口结构

分页接口 (path 含 /page) 的 data 结构:

```json
{
  "code": 200,
  "message": "SUCCESS",
  "data": {
    "list": [...],
    "total": 607,
    "pageSize": 5,
    "pageNum": 1
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| data.list | array | 数据列表 |
| data.total | int | 总记录数 |
| data.pageSize | int | 每页大小 |
| data.pageNum | int | 当前页码 |

**注意: 使用 `list` 而非 `records`/`rows`。**

## 6. 列表接口结构

列表接口 (path 含 /list) 的 data 直接是数组:

```json
{
  "code": 200,
  "message": "SUCCESS",
  "data": [
    {"uuid": "...", "currencyName": "人民币", ...},
    ...
  ]
}
```

## 7. 详情/Info 接口

成功时 data 为对象, 失败时 data 为 null:

```json
{
  "code": 400,
  "message": "查询数据失败",
  "data": null
}
```

## 8. 404 (网关级别)

真正不存在的路径返回网关级 404 (无 code/message):

```json
{
  "timestamp": "...",
  "status": 404,
  "error": "Not Found",
  "path": "/nonexistent/api/xyz"
}
```

## 9. 断言策略建议

| 层级 | 断言 | 必选 |
|------|------|------|
| L1 | status_code == 200 | 是 |
| L2 | $.code 存在 | 是 |
| L3 | $.code == 200 (业务成功) | 是 |
| L4-page | $.data.list 为 array | 分页接口 |
| L4-page | $.data.total 存在 | 分页接口 |
| L4-list | $.data 为 array | 列表接口 |
| L4-info | $.data 非 null | 详情接口 |
| L5 | AI 补充字段级断言 | 可选 |
