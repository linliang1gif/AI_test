# 测试用例生成器

这个 skill 帮助你根据需求文档生成高质量、全面的测试用例。

## 核心能力

1. **需求分析** - 深入理解需求文档，识别关键功能点
2. **模块拆分** - 将系统拆分为独立的功能模块
3. **测试点识别** - 从多个维度识别测试点
4. **场景设计** - 设计全面的测试场景矩阵
5. **用例生成** - 生成详细的测试用例

## 测试维度

生成测试用例时，必须覆盖以下维度：

### 1. 功能测试
- 正常流程验证
- 核心功能验证
- 业务规则验证

### 2. 边界测试
- 最小值/最大值
- 临界值
- 空值/null
- 超长数据

### 3. 异常测试
- 非法输入
- 错误参数
- 异常状态
- 系统故障

### 4. 安全测试
- SQL 注入
- XSS 攻击
- 权限控制
- 数据加密

### 5. 性能测试
- 响应时间
- 并发处理
- 资源占用
- 压力测试

### 6. 兼容性测试
- 不同浏览器
- 不同设备
- 不同分辨率
- 不同操作系统

## 测试用例结构

每个测试用例必须包含：

```
- 用例标题：简洁明确，描述测试目的
- 所属模块：功能模块名称
- 测试点：对应的测试点
- 优先级：高/中/低
- 前置条件：执行测试前需要满足的条件
- 测试步骤：详细的操作步骤（至少5步）
- 测试数据：具体的输入数据（要具体，不要写"有效数据"）
- 预期结果：明确的预期输出和行为
- 测试类型：功能/边界/异常/安全/性能/兼容性
```

## 数量要求

- 每个模块至少生成 **100个** 测试用例
- 每个测试点至少生成 **20个** 场景
- 每个场景至少生成 **5个** 用例

## 质量标准

### 测试步骤要求
- 至少 5 步
- 每步都要具体可执行
- 包含具体的操作和验证

### 测试数据要求
- 给出具体的示例值
- 不要写"有效数据"、"无效数据"等笼统描述
- 包含边界值和特殊字符

### 标题要求
- 简洁明确（不超过30字）
- 不要包含"测试用例标题:"等前缀
- 不要包含场景详细信息

## 示例

### 好的测试用例标题
✅ "验证用户登录功能"
✅ "测试订单列表排序"
✅ "检查支付金额计算"

### 不好的测试用例标题
❌ "测试用例标题: 验证用户登录功能"
❌ "功能测试点1-输入数据：有效数据 用户状态：已登录..."
❌ "测试"

### 好的测试数据
✅ "用户名: test@example.com, 密码: Test123456!"
✅ "订单金额: 9999.99, 商品数量: 100"
✅ "特殊字符: <script>alert('xss')</script>"

### 不好的测试数据
❌ "有效数据"
❌ "正常输入"
❌ "测试数据"

## 使用方法

当用户上传需求文档时：

1. 仔细阅读需求文档
2. 识别所有功能模块
3. 为每个模块生成测试点
4. 设计测试场景矩阵
5. 生成详细的测试用例
6. 确保数量和质量都达标

## 注意事项

- 测试用例要覆盖所有重要场景
- 测试步骤要详细具体
- 测试数据要真实可用
- 预期结果要明确清晰
- 优先级要合理分配
