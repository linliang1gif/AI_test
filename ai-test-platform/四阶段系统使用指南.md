# 四阶段 AI 测试系统使用指南

## 🎯 系统简介

四阶段 AI 测试系统是一个完全自动化的测试决策与执行平台，包含：

1. **Test Agent** - AI 决策中心：分析需求，判断是否需要测试
2. **Strategy Engine** - 策略引擎：生成详细的测试策略
3. **Orchestrator** - 执行调度器：自动调度并执行测试
4. **Self-Healing** - 自动修复：分析失败原因并自动修复

## 📖 使用场景

### 场景1: 完整自动化流程（推荐）

**适用**: 新功能开发，需要完整的测试决策和执行

```python
import requests

BASE_URL = "http://localhost:8000/api"

# 步骤1: Test Agent 分析需求
agent_result = requests.post(f"{BASE_URL}/agent/analyze", json={
    "requirement": "支付模块需要支持微信支付和支付宝支付",
    "git_diff": "+def wechat_pay():\n+    return process_payment('wechat')",
    "context": {
        "priority": "P0",
        "module": "支付模块"
    }
}).json()

print(f"需要测试: {agent_result['need_test']}")
print(f"测试类型: {agent_result['test_types']}")

# 步骤2: Strategy Engine 生成策略
strategy_result = requests.post(f"{BASE_URL}/strategy/generate", json={
    "agent_decision": agent_result
}).json()

print(f"生成策略: {len(strategy_result['strategy'])} 个模块")

# 步骤3: Orchestrator 执行测试
orchestrator_result = requests.post(f"{BASE_URL}/orchestrator/run", 
    json=strategy_result
).json()

print(f"执行结果: {orchestrator_result['summary']['passed']}/{orchestrator_result['summary']['total']} 通过")

# 步骤4: Self-Healing 修复失败用例
for result in orchestrator_result['results']:
    if result['status'] == 'failed':
        healing_result = requests.post(f"{BASE_URL}/healing/fix", json={
            "module": result['module'],
            "error": result['details'],
            "test_type": "api"
        }).json()
        
        print(f"修复 {result['module']}: {healing_result['fixed']}")
        if healing_result.get('retry_result'):
            print(f"重试结果: {healing_result['retry_result']['status']}")
```

### 场景2: 仅使用 Self-Healing

**适用**: 已有测试失败，需要快速修复

```python
# 直接修复失败的测试
result = requests.post(f"{BASE_URL}/healing/fix", json={
    "module": "支付模块",
    "error": "AssertionError: expected 200 but got 500",
    "test_type": "api"
}).json()

if result['fixed']:
    print(f"✅ 修复成功: {result['fix_strategy']}")
    print(f"   置信度: {result['confidence']}")
    
    if result['retry_result']['status'] == 'passed':
        print(f"   ✅ 重试通过")
    else:
        print(f"   ⚠️  重试仍失败，需要人工介入")
else:
    print(f"❌ 无法自动修复: {result['reason']}")
```

## 🔧 Self-Healing 详细使用

### 支持的错误类型

| 错误类型 | 识别关键词 | 修复策略 | 成功率 |
|---------|-----------|---------|--------|
| assertion | AssertionError, expected | 调整断言期望值 | 90% |
| timeout | Timeout, timed out | 增加超时时间 | 85% |
| server_error | 500, 502, 503 | 添加重试机制 | 80% |
| not_found | 404, not found | 尝试备用路径 | 70% |
| auth_error | 401, 403, unauthorized | 刷新 token | 75% |
| connection | connection, refused | 无法自动修复 | 0% |

### 修复流程

```
测试失败
    ↓
分析错误类型
    ↓
提取错误上下文
    ↓
应用修复策略
    ↓
重新执行测试
    ↓
记录修复日志
```

### 修复限制

1. **最多重试 1 次**: 防止死循环
2. **不修改真实代码**: 只模拟修复
3. **需要人工介入**: connection 和 unknown 类型

## 🎓 最佳实践

## 🐛 故障排查

### 问题1: Self-Healing 不工作

**症状**: 调用 `/healing/fix` 返回错误

**排查步骤**:
```bash
# 1. 检查模块健康
curl http://localhost:8000/api/healing/health

# 2. 查看后端日志
# 检查 Terminal 36 输出

# 3. 运行单元测试
python test_self_healing.py
```

### 问题2: 修复成功率低

**症状**: `success_rate` < 70%

**优化方法**:
1. 查看失败的错误类型
2. 优化对应的修复策略
3. 增加错误类型识别规则

### 问题3: 重试一直失败

**症状**: `retry_result.status` 总是 `failed`

**原因**: 
- Mock 模式下有 30% 失败率（模拟真实场景）
- 实际使用时会调用真实的测试执行器

## 📝 API 参考

### POST /api/healing/fix

**请求**:
```json
{
  "module": "支付模块",
  "error": "AssertionError: expected 200 but got 500",
  "test_type": "api"
}
```

**响应**:
```json
{
  "fixed": true,
  "reason": "调整断言：期望值从 200 改为 500",
  "confidence": 0.8,
  "error_analysis": {
    "type": "assertion",
    "severity": "medium",
    "fixable": true
  },
  "fix_strategy": "调整断言：期望值从 200 改为 500",
  "retry_result": {
    "status": "passed",
    "duration": 0.1
  }
}
```

### GET /api/healing/statistics

**响应**:
```json
{
  "success": true,
  "data": {
    "total_healings": 22,
    "successful_fixes": 18,
    "failed_fixes": 4,
    "success_rate": 81.82,
    "avg_confidence": 0.67
  }
}
```

### GET /api/healing/suggestions/{error_type}

**参数**: error_type = assertion | timeout | server_error | not_found | auth_error | connection

**响应**:
```json
{
  "success": true,
  "error_type": "assertion",
  "suggestions": [
    "检查期望值是否正确",
    "验证响应格式是否变化",
    "考虑放宽断言条件"
  ]
}
```
