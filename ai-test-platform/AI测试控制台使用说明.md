# AI测试控制台使用说明

## 🚀 功能概述

AI测试控制台是五阶段自动化测试系统的前端界面，提供一键执行完整测试流程的能力。

## 📍 访问路径

```
http://localhost:5173/ai-test-console
```

## 🎯 核心功能

### 1. 输入区域

**需求描述**（必填）
- 描述本次变更的需求
- 例如："支付模块需要支持微信支付和支付宝支付"

**Git Diff**（可选）
- 粘贴代码变更内容
- 帮助AI更准确地判断影响范围
- 例如：
  ```diff
  +def wechat_pay():
  +    return process_payment('wechat')
  ```

**优先级**
- P0: 核心功能（支付、登录、订单等）
- P1: 重要功能（用户管理、商品管理）
- P2: 一般功能（日志、配置）

### 2. 执行流程

点击"🚀 Run AI Test"后，系统会自动执行五个阶段：

```
1️⃣ AI决策分析 (Test Agent)
   ├─ 判断是否需要测试
   ├─ 评估风险等级
   └─ 输出决策指令

2️⃣ 生成测试策略 (Strategy Engine)
   ├─ 应用业务规则
   ├─ 生成测试计划
   └─ 确定测试类型

3️⃣ 执行测试 (Orchestrator)
   ├─ 并行调度测试
   ├─ 运行测试用例
   └─ 收集执行结果

4️⃣ 自动修复 (Self-Healing)
   ├─ 分析失败原因
   ├─ 应用修复策略
   └─ 自动重试验证

5️⃣ 生成报告 (Report)
   ├─ 统计测试结果
   ├─ AI总结风险点
   └─ 生成完整报告
```

### 3. 结果展示

**AI决策卡片**
- 是否执行：✅ 需要测试 / ⏭️ 跳过
- 优先级：P0 / P1 / P2
- 风险等级：高 / 中 / 低
- 置信度：0-100%

**测试策略卡片**
- 显示每个模块的测试类型
- 显示执行顺序
- 显示测试范围

**执行过程卡片**
- 总数 / 通过 / 失败统计
- 每个测试的详细结果
- 执行耗时

**自愈过程卡片**
- 修复次数 / 成功修复统计
- 每个修复的详细信息
- 修复策略和置信度

**最终报告卡片**
- 测试状态：✅ 通过 / ❌ 失败 / ⏭️ 跳过 / ⚠️ 部分通过
- 通过率进度条
- AI分析总结
- 执行时间线
- Trace ID（用于追踪）

## 📖 使用场景

### 场景1: 代码提交前验证

```
1. 完成代码开发
2. 复制 git diff 内容
3. 在控制台输入需求描述和 git diff
4. 点击"Run AI Test"
5. 查看测试结果
6. 如果通过，提交代码
```

### 场景2: Bug修复验证

```
1. 修复Bug后
2. 输入Bug描述作为需求
3. 选择优先级（根据Bug严重程度）
4. 执行测试
5. 确认修复效果
```

### 场景3: 新功能快速验证

```
1. 开发新功能
2. 输入功能描述
3. 粘贴代码变更
4. 执行测试
5. 查看AI分析的风险点
```

## 🎨 界面说明

### 左侧：输入区域

- **需求描述框**：多行文本输入
- **Git Diff框**：代码格式输入（等宽字体）
- **优先级按钮**：三个按钮选择
- **执行按钮**：蓝色渐变大按钮
- **清空按钮**：灰色按钮

### 右侧：结果展示

- **执行进度**：5个阶段的进度指示器
- **结果卡片**：多个可折叠的信息卡片
- **空状态**：未执行时显示提示

## 🔍 状态说明

### 执行状态

- **运行中**：按钮显示"⚙️ 执行中..."，禁用输入
- **完成**：显示完整结果，可以再次执行
- **错误**：显示错误提示

### 测试状态

- **✅ 通过**：绿色背景
- **❌ 失败**：红色背景
- **⏭️ 跳过**：灰色背景
- **⚠️ 部分通过**：黄色背景

### 优先级颜色

- **P0**：红色（核心功能）
- **P1**：黄色（重要功能）
- **P2**：蓝色（一般功能）

### 风险等级颜色

- **高**：红色
- **中**：黄色
- **低**：绿色

## 💡 使用技巧

### 1. 需求描述建议

**好的示例**：
```
支付模块需要支持微信支付，包括扫码支付和H5支付
```

**不好的示例**：
```
改了点代码
```

### 2. Git Diff建议

**包含关键信息**：
```diff
+def wechat_pay(order_id, amount):
+    # 调用微信支付API
+    return process_payment('wechat', order_id, amount)
```

**避免过长**：
- 只粘贴关键变更
- 不要粘贴整个文件

### 3. 优先级选择

- **P0**：支付、登录、订单等核心功能
- **P1**：用户管理、商品管理等重要功能
- **P2**：日志、配置等一般功能

### 4. 结果分析

- 关注AI分析的风险点
- 查看失败的详细原因
- 检查自愈是否成功
- 保存Trace ID用于追踪

## 🔧 故障排查

### 问题1: 点击按钮无反应

**原因**：需求描述为空  
**解决**：输入需求描述

### 问题2: 执行失败

**原因**：后端服务未启动  
**解决**：
```bash
python backend_api_server.py
```

### 问题3: 结果显示不完整

**原因**：网络超时  
**解决**：刷新页面重试

### 问题4: AI分析不准确

**原因**：需求描述不清晰  
**解决**：提供更详细的需求描述和Git Diff
