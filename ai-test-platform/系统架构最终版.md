## 模块详细说明

### 阶段1: Agent (需求理解 + AI决策)
**职责**: 分析需求和代码变更，决定是否需要测试

**传统能力**:
- `RequirementParser`: 解析需求文档结构
- `ModuleSplitter`: 识别功能模块

**AI能力**:
- LLM 决策分析: 评估风险等级、测试类型

**输入**: 
- requirement (需求文档)
- git_diff (代码变更)
- priority (优先级)

**输出**:
```python
{
    "need_test": bool,
    "action": "run_tests" | "skip",
    "risk_level": "高" | "中" | "低",
    "test_types": ["api", "ui", "integration"],
    "parsed_modules": [...],  # 传统能力
    "confidence": 0.8
}
```

### 阶段2: Strategy (测试规划)
**职责**: 根据决策生成测试策略

**能力**:
- 规则引擎: 优先级 + 风险 → 测试类型
- 用例数量估算

**输入**: decision

**输出**:
```python
{
    "strategy": [
        {
            "module": {"name": "支付模块"},
            "test_types": ["api", "ui", "integration"],
            "case_count": 30,
            "execution_hint": {"parallel": True}
        }
    ],
    "total_cases": 90
}
```

### 阶段3: Case Generator (传统能力重用) [可选]
**职责**: 生成详细测试用例

**传统能力**:
- `ScenarioBuilder`: 构建测试场景
- `CaseBuilder`: 生成测试用例

**特性**:
- 优先级过滤: P0→正常+异常+边界, P1→正常+异常, P2→正常
- 不依赖需求文档（只依赖 strategy）
- 支持 no-LLM 模式

**输入**: strategy

**输出**:
```python
{
    "cases": [
        {
            "module": "支付模块",
            "cases": [
                {"id": "TC_01", "title": "支付成功", "type": "api"},
                {"id": "TC_02", "title": "支付失败", "type": "api"}
            ]
        }
    ],
    "total_cases": 9
}
```

### 阶段4: Orchestrator (执行 + 脚本生成)
**职责**: 调度和执行测试

**能力**:
- 双模式执行:
  - `run_by_cases()`: 基于用例列表
  - `run_by_strategy()`: 基于策略
- 三种 Runner: ApiRunner, UiRunner, IntegrationRunner
- 并发执行
- 脚本生成 (ApiScriptGenerator) [TODO]

**输入**: strategy, cases (optional)

**输出**:
```python
{
    "mode": "cases" | "strategy",
    "results": [
        {
            "module": "支付模块",
            "status": "passed",
            "case_results": [...]  # cases 模式
        }
    ],
    "summary": {
        "total": 3,
        "passed": 2,
        "failed": 1,
        "pass_rate": 66.67
    }
}
```

### 阶段5: Self-Healing (失败修复) [按需]
**职责**: 自动分析和修复失败的测试

**能力**:
- `ErrorAnalyzer`: 识别 6 种错误类型
- `Fixer`: 应用修复策略
- 重试机制

**触发条件**: execution.failed > 0

**输入**: execution

**输出**:
```python
{
    "records": [
        {
            "module": "支付模块",
            "fixed": True,
            "fix_strategy": "parameter_adjustment",
            "retry_status": "passed"
        }
    ],
    "statistics": {
        "total_healings": 1,
        "successful_fixes": 1
    }
}
```

### 阶段6: Report (覆盖率 + AI总结) [V2]
**职责**: 生成测试报告和覆盖率分析

**V2 新增能力**:
- 覆盖率分析 (case_based / strategy_based)
- 传统覆盖率接入 (CoverageAnalyzer)
- AI 总结增强 (JSON格式)
- 修复统计集成

**输入**: 所有阶段数据

**输出**:
```python
{
    "summary": {
        "status": "passed" | "partial" | "failed",
        "total": 3,
        "passed": 3,
        "failed": 0,
        "pass_rate": 100.0
    },
    "coverage": {  # V2 新增
        "mode": "case_based",
        "total_cases": 9,
        "executed_cases": 9,
        "coverage_rate": 100.0,
        "module_coverage": [...]
    },
    "traditional_coverage": {...},  # V2 新增
    "ai_analysis": "{...}",  # V2 增强
    "details": [...]
}
```

## TestContext 统一数据模型

```python
@dataclass
class TestContext:
    # 输入数据
    requirement: str
    git_diff: str
    priority: str = "P1"
    
    # 配置
    use_case_generator: bool = True
    
    # 阶段输出
    decision: Optional[Dict] = None
    strategy: Optional[Dict] = None
    cases: Optional[Dict] = None
    execution: Optional[Dict] = None
    healing: Optional[Dict] = None
    report: Optional[Dict] = None
    
    # 元数据
    trace_id: str = auto_generated
    created_at: str = auto_generated
    timeline: List[Dict] = []
```

**核心方法**:
- `is_skip()`: 判断是否跳过测试
- `should_heal()`: 判断是否需要修复
- `add_timeline_event()`: 记录时间线
- `get_total_duration()`: 计算总耗时
- `to_dict()` / `from_dict()`: 序列化

## 两种执行模式

### 完整模式 (use_case_generator=True)
```
Agent → Strategy → Case Generator → Orchestrator(cases) → Healing → Report
```
- 生成详细测试用例
- 基于用例执行
- 覆盖率 = executed_cases / total_cases
- 适合: 完整测试、详细报告

### 快速模式 (use_case_generator=False)
```
Agent → Strategy → Orchestrator(strategy) → Healing → Report
```
- 跳过用例生成
- 基于策略执行
- 覆盖率 = 100% (假设全部执行)
- 适合: 快速验证、CI/CD

## 核心设计原则

### 1. 统一数据流
- 单一数据对象: TestContext
- 所有模块只接收 context
- 不再传多个 JSON
- Pipeline 只传 context

### 2. 模块解耦
- 禁止跨模块直接调用
- 只依赖 TestContext 接口
- 易于扩展和维护

### 3. 流程可插拔
- Case Generator 可启用/禁用
- Self-Healing 按需触发
- 支持提前退出

### 4. 传统能力重用
- Agent: 需求解析
- Case Generator: 用例生成
- Report: 覆盖率分析

### 5. AI 能力增强
- Agent: 决策分析
- Report: 智能总结

## 使用示例

### Python 调用
```python
from pipeline.pipeline_service import get_pipeline_service

pipeline = get_pipeline_service()

result = pipeline.run_pipeline({
    "requirement": "需求文档",
    "git_diff": "代码变更",
    "priority": "P0",
    "use_case_generator": True
})

print(f"Trace ID: {result['trace_id']}")

```
